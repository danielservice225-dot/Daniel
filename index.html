Limites à connaître

Compatibilité de la reconnaissance vocale

La Web Speech API est principalement disponible dans Chrome et Edge, avec une prise en charge variable dans Safari. Firefox ne propose généralement pas SpeechRecognition. La synthèse vocale et les voix installées varient selon le système. En cas d’indisponibilité, le clavier et toutes les commandes locales restent utilisables.

HTTPS, micro et fonctionnement en arrière-plan

L’accès au microphone et à la caméra exige HTTPS ou localhost. Une interaction utilisateur peut être demandée. Le mot déclencheur ne fonctionne pas lorsque l’onglet est fermé et peut être suspendu en arrière-plan par le navigateur ou le système.

Ouverture d’applications et bloqueurs de fenêtres

Daniel ouvre les versions web des services, pas leurs applications natives. Après une reconnaissance vocale asynchrone, certains navigateurs bloquent window.open. Chaque réponse de lancement contient donc un lien cliquable de secours.

Mode local et intelligence générative

Sans backend, Daniel exécute les commandes intégrées mais ne prétend pas être un modèle génératif complet. Connectez le projet FastAPI fourni et configurez un fournisseur d’IA pour les réponses ouvertes. Aucune clé secrète ne doit être placée dans le HTML.

Confidentialité du service vocal du navigateur

Selon le navigateur, SpeechRecognition peut transmettre l’audio à un service du fournisseur. Daniel n’enregistre pas ce flux, mais ne peut pas garantir le fonctionnement interne du navigateur. Consultez ses réglages de confidentialité et utilisez la saisie écrite si nécessaire.

Cycle d’une interaction

  1. Un clic, une saisie ou le mot déclencheur active l’écoute.
  2. L’orbe passe successivement en écoute, réflexion puis parole.
  3. Les commandes sensibles et lancements restent dans une liste locale contrôlée.
  4. Une question ouverte est envoyée au backend uniquement si une URL API est configurée.
  5. La réponse est affichée comme texte sûr et lue si les réponses vocales sont activées.

Démarrer en quelques minutes.

Prérequis : Python 3.11 ou supérieur, un navigateur récent et un terminal. Le frontend seul peut aussi être ouvert directement, mais localhost est recommandé pour les permissions.

  1. 1
    Télécharger et extraire l’archive

    Ouvrez un terminal dans le dossier daniel-aura.

  2. 2
    Créer l’environnement virtuel

    Python 3.11+ est recommandé pour toutes les dépendances fournies.

  3. 3
    Installer et configurer

    Copiez .env.example vers .env. La clé du fournisseur est facultative pour tester l’API, nécessaire pour l’IA générative.

  4. 4
    Lancer Uvicorn

    Ouvrez ensuite http://localhost:8000 et testez /api/health.

macOS / Linux

python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --host 0.0.0.0 --port 8000 --reload

.venv\Scripts\Activate.ps1

Des limites explicites, une sécurité réaliste.

Ce projet est prêt pour une démonstration locale complète. Un déploiement public nécessite les durcissements habituels de l’infrastructure.

Navigateur et voix

  • SpeechRecognition est absent ou partiel selon les navigateurs ; le clavier constitue le fallback officiel.
  • La reconnaissance peut dépendre d’un service cloud du navigateur et d’une connexion réseau.
  • Les voix, langues et comportements de SpeechSynthesis varient selon l’appareil.
  • Le mot déclencheur est expérimental et ne garantit pas une écoute permanente en arrière-plan.

Permissions et données

  • Micro et caméra exigent HTTPS ou localhost, un matériel disponible et l’accord de l’utilisateur.
  • La caméra n’est jamais enregistrée par l’application ; fermer l’aperçu arrête chaque piste média.
  • L’historique local est limité à 40 messages et désactivé par défaut.
  • Effacer les données du navigateur ou désactiver le stockage supprime les préférences conservées.

Applications et IA

  • Seules les versions web HTTPS listées sont lancées. Les applications natives ne sont pas contrôlées.
  • Les bloqueurs de pop-up peuvent empêcher l’ouverture automatique ; le lien de secours reste disponible.
  • Le mode local n’est pas un modèle génératif et répond uniquement aux intentions prévues.
  • Une réponse générative peut contenir des erreurs. Vérifiez toute information importante.

Déploiement public

  • Ajoutez authentification, limitation de débit distribuée, journalisation non sensible et supervision.
  • Utilisez HTTPS, des origines CORS exactes, un proxy inverse et une politique CSP adaptée à votre hébergement.
  • Conservez les secrets dans votre gestionnaire de variables d’environnement. Ne versionnez jamais .env.
  • Le quota et les coûts du fournisseur d’IA doivent être contrôlés côté serveur.
